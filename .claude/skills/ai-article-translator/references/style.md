# 排版规范

## 中文标点（全角）

强制全角：`，` `。` `：` `；` `？` `！` `"` `"` `'` `'` `——` `……` `、` `《》`。

不要用半角逗号句号在中文里。英文短语嵌在中文里（如"agentic 编码是一项 skill"），两侧不加空格，句末仍用全角句号。

## 中英文之间的空格

- 中英文之间加半角空格：`使用 Claude 时`，不是`使用Claude时`。
- 中文与阿拉伯数字之间加空格：`用了 3 天`。
- 中文标点（全角）与英文之间不加空格：`结论：Claude 更快`，不是`结论： Claude 更快`。

## 代码 / 命令 / 路径

- 代码块整块保留英文，不翻译，不加注释。若用户看不懂会追问。
- 内联代码 `code` 保留英文原文。
- 命令行、CLI flag、文件路径全部保留。

## 提示词范例（prompt example）

- 逐句对照译中文。
- 英文原文用样式 `.prompt-en`，中文译文用样式 `.prompt-zh`，紧接在英文下方。

## 图片

**核心原则：图片是正文的一部分，必须按原文位置插入，不能全部堆到文末。**

- 抓原文时用 DOM walk（见 SKILL.md 第 1 步），保留图文交错顺序。翻译成品里，`<img>` 应插在它在原文中所属的段落之后。
- 若通过 URL 抓到原文，`<img src>` 保留原始 URL，加 `referrerpolicy="no-referrer"`（避免 `pbs.twimg.com` 等图床的 referer 校验失败）。不要下载到本地。
- 若从 SingleFile HTML 抓到，`<img src="data:image/...;base64,...">` 直接省略该 `<img>` 标签，并在译文位置加一行注释 `<!-- 原文此处有图，base64 已省略 -->`。
- 过滤掉非正文图：头像（`profile_images/`）、emoji、UI 图标、广告位。判定看 DOM 位置（是否在正文语义容器内），不要靠 alt（X 的 alt 常是 "Article cover image" 这种通用值，不可信）。
- 图片不做译文（alt 可保留原文或改简短中文，非重点）。

## 链接

- 保留原始 `<a href>`。
- 链接文字若为英文短语（如 "read more here"），中文段落里译成"点这里"或"这里"，不要生造英文短语的直译。

## 段落对照结构

每段英文原文紧跟一段中文译文，不用逐句穿插。翻译单位是段落。列表则整个 `<ul>` 后紧跟中文 `<ul>`。

## 术语一致

同一术语在一篇文章内译名固定，遵守 glossary.md。

## 保守 vs 意译

- 技术准确性 > 中文流畅度。若意译可能丢失概念（如 "agentic" 直译"能动的"）保留英文。
- 隐喻性英文谚语（如 "the map is not the territory"）用中文直译 + 括注解释。
- 长句可拆短，但不合并不同段落。
- **优先直白口语，避免晦涩书面语。** 例如 pitch → "卖点介绍" 优于"推介"；buy-in → "认同" 优于"获取支持"。能用常见词就别用生僻词。
