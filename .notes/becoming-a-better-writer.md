# Becoming a Better Writer

## 元信息
- 作者：Gergely Orosz（The Pragmatic Engineer newsletter）
- 原文：https://newsletter.pragmaticengineer.com/p/becoming-a-better-writer
- 译文：`Becoming a Better Writer - 双语.html`
- 主题：面向软件工程师 / 工程经理 / 高管的职场写作提升指南。2026-10 前为付费文章，之后设为免费。
- 备注：严格说不属 AI Agent 领域（写作技巧类），用户明确点名用 ai-article-translator 翻译。

## 核心观点

### 为什么写作重要
- 远程办公和分布式团队普及，过硬写作能力是多数工程领导岗的基本门槛。Amazon 工程经理筛选第一步就是写作练习；Stripe（Staff+）、TrueLayer（principal）面试也有写作环节。
- 高速成长创业公司/大厂的工程师，每天写的字可能比代码还多：commit 说明、code review 评论、聊天、邮件、规划文档、PRD 评论、复盘报告、绩效材料。资历越高写得越多（会议纪要、提案、项目更新、演示）。
- 组织越大、岗位影响力越大，文字触达的人越多。引 Sinofsky《Writing is Thinking》：关注功能而非形式。

### 写好的流程：写作 → 编辑 → 获取反馈

八条编辑法（原文编号）：
1. 拆成易读小块，一段一个想法；按载体调段长（手机邮件更短）。
2. 删不必要/分散注意力的内容。Amazon 六页纸上限、偏爱一页摘要——有限制才让每段宝贵。Pascal："我本想写一封更短的信，可惜没时间。"删客套填充词。
3. 用更短句子，推荐 Hemingway Editor 标出可拆分处。
4. 查语法，用 Grammarly（可报销）。
5. 合适处用项目符号/编号；条目太长就并成段；多段内容的列表用编号便于读者定位。
6. 克制加粗，留给关键要点；别在句中加粗，重组句子让粗体落在开头。
7. 用视觉元素，截图/图示胜千言；引 Cloudflare 2021 Facebook 宕机复盘几乎每段配图。
8. 看重读者时间甚于自己——发给越多人越要花时间编辑。

### 获取反馈
- 放 Google Docs 等协作编辑器异步求反馈。
- 别泛泛求反馈，问具体问题（"最困惑的是哪部分""哪部分多余"）。
- 几乎所有人求的反馈都太少；像结对编程一样多问无妨。
- 雇编辑最贵但高质量；免费途径：给提供编辑的刊物投稿（Who Pays Technical Writers）。
- 自动化工具（Hemingway/Grammarly）能大幅提升可读性，但别全盘接受不认同的建议；越自信越会无视建议。

### 提升写作的三条路
1. **观察并模仿优秀写作**：读放不下手的小说、分析其文风；收藏工作内外最好的邮件/规划文档/复盘/PRD/工单/讨论串，当模板照着写。
2. **养成习惯**：先学盲打；挑最重要/传播最广的文字投入编辑+反馈。适合的练习：每周 5-15 更新、给利益相关方的每周项目摘要、主动记会议纪要、倡议提案、设计文档（可视化工具 Excalidraw / Lucidchart / Miro）、文档。
3. **持续学习**：书《On Writing Well》（Zinsser）、《The Elements of Style》（Strunk & White）、《Dreyer's English》；Google 技术写作课；Leadership Lab《The craft of writing effectively》——"写作不是解释你的想法，而是改变读者的想法"（Stefan Buck 总结）。

### 结论
- 资历越深写作越重要；写作短板会卡住某些层级的晋升。
- 系统方法：编辑草稿 → 获取反馈迭代 → 观察模仿 → 建立习惯（至少每周）→ 持续学习。
- 在越来越依赖文字的世界，技术能力 + 写作能力 = 超能力。最佳开始时机是现在。
