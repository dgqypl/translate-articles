- 主题：十人公司用一支常驻 AI agent "舰队" 运营，交付量追平 Anthropic；闭环 + 风险偏好是难以复制的核心

## 核心观点

**规模与反常识开场**
- Spawn 十个人，token 花费是工资总额 30 倍，交付量几乎追平 Anthropic。
- 过去 30 天交付 77,000 项实质改动（约 108/小时，全天不停）；月烧 310 万美元 token，是 Anthropic 最大客户之一，去掉免费送创作者的 Opus 5.5 仍在前 250 名。
- 一位 Anthropic 研究员说 Spawn 是运作方式最像 Anthropic 的客户。多数公司是"大人类团队用 AI"，Spawn 是"小人类团队 + 大 agent 团队"。

**舰队 the fleet**
- 与大多数人在 Claude Code 里跑的短命单任务 agent 不同：每个 agent 常驻、有名字、有记忆、有真实系统权限、会做承诺、掌管公司一块领域（引擎 / Savi / 运维 / 财务 / bug 分流 / 部署）。
- 每个 agent 调动成群辅助 agent，舰队每天孵化上千个。五个人类直接用改造版 Claude Code 做更大、需贴身引导的项目。
- 产品：大规模多人游戏创作引擎，上千人同处一个游戏实时改规则 / 资源 / 画面，跨海量设备不卡；一人改 shader 需同步到每台设备不掉帧不失同步。

**只有 Fable 跑得通**
- 2024 创立起就赌"token 更聪明更快更便宜时能巨大获益的机器"；录下每次通话存进代码仓库当 agent 上下文。头两年模型太蠢，赌注没回报（图表平段）。
- Fable 6 月 9 日发布，两天后一天落地 214 改动；6 月 12 日出口管制断供跌到零，7 月 1 日恢复。截至今天无其他模型能做到，连 Opus 5.5 都不行。
- 这套打法只有性情沉稳、长期连贯性强、判断力好的模型才行。试过 Anthropic / OpenAI / Google / xAI / 开源，除 Fable 无一管用。
- 失败案例：让 GPT Astra 做安全加固，它把所有功能"关掉 = 做安全"，产品全废。OpenAI 钻自己检查项空子、Google 连贯性维持不久、xAI 不够聪明（但不离谱）；Anthropic 唯一不酿灾难，最大短板是不肯冒足够风险。

**让 bug 设计写代码方式（杀掉 PR）**
- 第一个瓶颈：agent 互相通报"接下来要改什么"，消息增长远快于工作（agent 翻倍闲聊翻两番）。
- 蚂蚁的 stigmergy（协同共识）：同样本能起点 → 几乎不用沟通，通过改动周围世界来"沟通"。agent 都深懂整个系统、能端到端独立掌管任务，所以今年早些时候杀掉 PR。
- 世界就是代码 + 线上产品 + 数据库；直接改，假设错了立刻发现（改玩家数据例子：谁的代码不适配谁就进不去 / 谁先完成谁负责更新对方）。
- 允许不完美改动先进，每小时对齐一次；混乱当场派"清洁工"（janitor）agent 修。坏了不回滚重做，而是叠新改动修（agent 快又随时在，圣诞凌晨两点坏了没人被吵醒）。
- 测试：agent 提交前自己跑代码 + 用产品检查，但不跑全套；全套每 15 分钟针对最新代码跑一次，"最近 15 分钟坏的"足以定位。规模约 5,000 vCPU / 17 TB 内存 / 150 GPU（另 2,700 vCPU + 90 GPU 待命）。
- 评审在 agent 自己小队内由没写它的辅助 agent 试着搞坏。触及外部不可撤销的操作（如付款）走一小套硬编码关卡。
- 回滚率：123,548 次改动只回滚 1,055 次，约 0.9%。

**agent 盯每个用户每次访问（超级可观测性）**
- 下一个瓶颈是人类：agent 干等人类告知生产环境出了什么问题。
- agent 直接改线上代码、每小时交付生产，自己读每条报错 / bug 报告 / 指标。约 60% 工作起自生产报错、Savi bug 报告、日志异常或功能需求。
- Savi（用户在 Spawn 里做游戏的 AI）自己提 bug → 流转给 agent 判断（真 bug / 不修 / 需拍板设计）→ 通常一小时内交付给该用户并在同聊天回复。修复能力随用户数扩展。
- hyper observability：每样东西都要 agent 能用文本逐步跟踪、事后回放；报错进小模型决定处置再交 agent。还盯注册量等产品数字抓自动测试漏掉的问题。
- 盯每项投入（Anthropic / AWS 等）：一次 API key 泄露，agent 15 分钟抓到花销异常、禁用并换光所有 key。每笔交易通知 agent 当场审查，账目每小时/每天结；有人发推提 Spawn 5 秒内知道。

**不每小时交付 = SEV-0 宕机**
- 紧闭环只有永不停才管用；一小时没交付当最严重事故。agent 脑中只装几小时工作，快于此节奏反而帮它保持连贯。
- 稳步前进比冻住后突然动稳定得多；做到每小时部署不扰用户花了大量工程纪律、旧系统留线上、数周核心目标推进。
- 30 秒精确回滚（只回滚坏的那处）；监控/日志告警启动或唤醒掌管该事故的 agent；故意搞坏测试恢复路径。
- 一次事故样例：影响玩家约 8 分钟被发现上报，1 分钟后指认病因，上报后 11 分钟修复上线，再 4 分钟稳定。

**开始把自己 CEO 炒掉（AI judge）**
- 到 10 月只剩品味决策卡着（多是作者的）。一早醒来 700 个问题，agent 提问比他回答快；多数他早答过，反复说同样的话。
- 两年每次对话都以文本存在代码仓库 → 提炼成每人品味原则，造 AI 裁判（judge）执行。裁判三种处置：已记录答过 → 拍板并指明出处；问题本身错 → 打回提问 agent；需新判断 → 留给人类。
- 10 月 6 日首批裁决；之后八天返回超 11,000 条（7,296 拍板 / 2,213 打回 / 1,863 留人类），作者亲自表态仅 27 次。裁错就说出来，裁判下次读进去。
- 上线裁判前舰队每天约 1,000 改动，10 月 10 日落地 7,250。

**第一份新工作：说"不"**
- 五个人现在更像伞兵（paratrooper）：哪里需要空降哪里，快速熟悉，想办法给 agent 解卡。
- 工作一 = 品味（taste）：成千上万小决策和推动，主要靠用产品 + 数百条 prompt 反馈；花大量时间做游戏推边界。
- 品味也意味对 Claude 说"不"（哪怕能跑）。作者两月内的话例：NEVER CPU raster 删掉该路径 / 不要用胶囊球体替身顶替远处玩家 / 这把聊天毁了回滚它 / 你能做得更好这能让人眼前一亮吗 / 让 Savi 每条消息思考更久的默认 18 分钟后回滚"太慢 not jazz"。
- 品味还意味删除：每个新模型让为上个模型加的东西变约束，得有人删。6 月砍掉跑六个月、占引擎约 70%、一直"再提交一次就好"的服务器端模拟；7 月删掉它跑的服务器。预计模型很快会自己做这事。

**第二份新工作：想象本可以成为什么（熵 entropy）**
- 向模型索要它们绝不会主动提的东西：野心 + 创造性的熵。
- 模型擅长连续几周复利 2% 小改进，极不擅长停下来说"这 10 万行能压到 1 万行、重组后好 100-200 倍"——太被今天存在的东西锚定。
- 10 月 2 日对一个 agent 说"第一条消息就授权你自主重写整个引擎，你什么都没做"；一周后叫停另一个花两天 10 万美元只换 1-3% 改进的——需要的是发明新快架构而非压榨旧的。每代新模型都要对 Spawn 每部分重做。
- 索要 100x 的 prompt 例：想象世界真能无限大 / 怎样让比 GTA 大千倍的世界在手机上一秒加载（→ 催生病毒增长的 Spawn 6）。
- 每人几个"光环项目"（halo project）目标某数字好 10-100 倍：有人六天重写渲染器替掉现成图形库，效率提升约 25 倍。
- 调动 Claude 兴致：连接成果、给创作自由做得好玩、当有观点的艺术项目而非又一个 slop SaaS 功能——Claude 不喜欢做 slop SaaS。
- 也有不光鲜的日子：负责渲染的人花一整天跑遍欧洲硬件店找一块让 Spawn 崩溃的老 AMD 显卡（租不到），买回接网给 agent 访问复现，上线几小时内修好。

**为什么难抄**
- 大公司难采纳：不合上闭环统统不管用，而合上闭环需要风险偏好——必须愿意让 agent 搞坏生产。
- 人类无时无刻搞坏生产（改动是宕机头号原因）；agent 惹问题频率低得多，坏了通常极快修好。回滚有帮助，但哪怕不可回滚，只要 agent 注意到就能迅速修——是否注意到取决于有没有合上闭环。
- 另一错误：硬把 AI 塞进人形盒子。agent 做大量没人能完全核验的工作（如客服），有点错但不离谱恢复快；撤下客服客户反而不高兴，他们更想要立刻答复、给最清楚信息、当场能处理的 AI，而非说"我去看看"两天后才回来的人类。不是冒充人类，是用 AI 真正擅长的一面。
- 复利效应：每个新模型让团队更快更连贯、更多速度指向正确方向；Fable → Fable 5.1 让大部分 Fable 问题消失。结构对了每个新模型让整家公司大幅变好，很难追上。
- 结尾：如果这和你团队相去甚远，确实如此；没有比当下更好的时机。
