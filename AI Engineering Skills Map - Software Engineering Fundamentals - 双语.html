Why Software Fundamentals Remain Essential for AI Developers 为什么软件基本功对 AI 开发者依然不可或缺

作者：Andrew Ng · 原文：https://x.com/AndrewYNg/status/2093388974194872781 · 中英双语对照 · 译文供个人阅读参考

Dear friends,

各位朋友：

How have software engineering fundamentals changed with agentic coding? Even when you use a coding agent to write all your code, understanding software fundamentals is important for steering your agent to make the tradeoffs you want — or to even know what tradeoffs exist to be made. Additionally, when you're building an AI application, the AI core is often expressed through a broader software application, which a skilled engineer will shape.

agentic 编码出现后，软件工程的基本功发生了什么变化？就算你让 coding agent 写下所有代码，理解软件基本功依然重要——它让你能引导 agent 做出你想要的取舍，甚至让你意识到有哪些取舍可做。此外，当你构建一个 AI 应用时，AI 内核往往要通过一个更大的软件应用来呈现，而这个软件应用要靠一名有本事的工程师来塑造。

A novice who vibe codes without understanding software fundamentals can create simple applications, but this often leads to the coding agent making bad tradeoffs in latency, availability, consistency, reliability, maintainability, simplicity, and/or cost. In most cases, the developer didn't know such tradeoffs even existed and therefore did not steer the agent to make the right decisions for their application context.

一个不懂软件基本功、只会 vibe coding 的新手能做出简单的应用，但这往往导致 coding agent 在延迟、可用性、一致性、可靠性、可维护性、简洁性和/或成本上做出糟糕的取舍。多数情况下，开发者根本不知道这些取舍存在，因此也没能引导 agent 针对自己的应用场景做出正确决策。

This letter describes what our study of AI Engineering Skills shows are the most important things to know in software engineering. It requires being skilled at:

这封信将介绍我们对 AI 工程技能的研究所显示的、软件工程中最需要掌握的东西。它要求你擅长：

  • Building full-stack applications
  • Managing data
  • Designing system architectures
  • Making systems secure and reliable
  • Scaling and operating in production
  • 构建全栈应用
  • 管理数据
  • 设计系统架构
  • 让系统安全可靠
  • 扩容并在生产环境中运维

Building full-stack applications.构建全栈应用。

Agentic coding enables many developers who previously played more specialized roles (like front-end developer or mobile developer) to play a broader, full-stack role. A coding agent can help with parts of the development process that you might be less familiar with. However, understanding how the full stack actually works is important. Skilled developers understand the key components and concepts of front-end and back-end systems, including UI components, caching, page rendering, API choice and design, authentication, state and session management, asynchronous processing, data persistence, testing, security, and accessibility.

agentic 编码让许多原本扮演专门角色（比如前端开发或移动端开发）的开发者，得以承担更宽泛的全栈角色。coding agent 能帮你搞定开发流程中那些你不太熟悉的部分。然而，理解整个技术栈究竟是怎么运作的仍然重要。有本事的开发者理解前后端系统的关键组件和概念，包括 UI 组件、缓存、页面渲染、API 的选型与设计、认证、状态与会话管理、异步处理、数据持久化、测试、安全和无障碍访问（accessibility）。

Managing data.管理数据。

Data deserves special attention because it is a foundation that software is built on top of, that is relatively hard to change (even if agents help with migrations). When you know how to manage data, you can think through access patterns and use them to decide what to store and for how long. You can identify the right data models and select the appropriate storage types (such as relational tables, documents, key-value, or graphs) and infrastructure, which in turn affects speed, scalability, availability, reliability, and cost. You understand transactions, concurrency, and how to ensure your data is clean, consistent, and fresh. When needed, you can ensure proper privacy, governance, and compliance. You know how to manage the data lifecycle.

数据值得特别关注，因为它是软件赖以搭建的地基，而且相对难改（即便 agent 能帮忙做迁移）。当你懂得管理数据，你就能想清楚访问模式，并据此决定存什么、存多久。你能识别出正确的数据模型，选择合适的存储类型（比如关系表、文档、键值或图）和基础设施，而这又会影响速度、可扩展性、可用性、可靠性和成本。你理解事务、并发，以及如何保证数据干净、一致、新鲜。必要时，你能确保恰当的隐私、治理与合规。你懂得如何管理数据的生命周期。

As an application evolves, you also know how to evolve the data architecture with it. Deciding how to manage data requires significant human-provided context. Your AI systems will get their own input context from your data source, so if data architecture is chosen poorly, the AI doesn't know what it doesn't know. This is why it takes skilled intervention from someone with the relevant context and skilled at AI engineering — you! — to set it right. How to build data infrastructure for agents — rather than only traditional software or humans — is also a rapidly evolving area, and you should continue to adjust your best practices as the field evolves.

随着应用演进，你还得懂得如何让数据架构随之演进。决定如何管理数据，需要大量由人来提供的上下文。你的 AI 系统会从你的数据源获取自己的输入上下文，所以如果数据架构选得不好，AI 就"不知道自己不知道什么"。正因如此，才需要一个既掌握相关上下文、又精通 AI 工程的人——也就是你！——来施以有本事的干预，把它理顺。如何为 agent（而不只是为传统软件或人）构建数据基础设施，也是一个快速演进的领域，你应当随着这个领域的发展不断调整自己的最佳实践。

Designing system architectures.设计系统架构。

When you understand the major components of the full stack of software and data, you are then better positioned to decide how to put the pieces together. Good system design requires understanding what the software is intended to do (how many users? how important is latency? how important is cost? etc.) so you can make choices about the application platform, the boundary between the frontend and backend, system decomposition, application state placement, and architectural granularity (monolith vs. microservices). You will also choose the stack (programming languages, runtimes, component/frontend/backend frameworks, data technologies) — sometimes by running experiments to evaluate options before settling on one.

当你理解了软件与数据整个技术栈的主要组件，你就更有能力决定如何把这些部件拼到一起。好的系统设计要求你理解这个软件想干什么（多少用户？延迟有多重要？成本有多重要？等等），这样你才能就以下方面做出选择：应用平台、前后端之间的边界、系统拆分、应用状态放在哪里，以及架构粒度（单体 vs. 微服务）。你还要选择技术栈（编程语言、运行时，组件/前端/后端框架，数据技术）——有时要先跑实验评估各个选项，再敲定一个。

Further, the right architecture is a moving target, depending on the phase of the project. The simple architecture you choose to build a quick prototype may not be the right architecture to build the first production system, and that too may change as the application scales. Making these decisions requires deep technical knowledge of both software components and the application context so you can design — and evolve — the architecture to make better tradeoffs.

再者，正确的架构是个移动的靶子，取决于项目所处的阶段。你为快速搭原型而选的简单架构，未必适合用来构建第一个生产系统，而后者又会随着应用扩容而改变。做这些决策需要对软件组件和应用场景都有深厚的技术认识，这样你才能设计——并演进——架构，做出更好的取舍。

Making systems secure and reliable.让系统安全可靠。

To build reliable systems, you should know how to develop testing strategies to verify the correctness of your system: What mix of unit tests and integration tests, what frameworks to use, and what level of coverage. You also know how to design around possible failures — how to handle failures (like an API hitting a rate limit), build in graceful degradation, and minimize the blast radius of failures. Additionally, rather than first writing software and then later figuring out how to secure it, the "shift left" movement is moving security work earlier in the lifecycle (to the left on a traditional project timeline). Just as all developers are moving toward becoming full stack developers, many developers are now also partly security engineers. You can now use AI tools to scan your code for vulnerabilities, check dependencies for supply chain injections, and examine your cloud configuration for attack surfaces. But doing this well still requires some knowledge of security.

要构建可靠的系统，你应当懂得如何制定测试策略来验证系统的正确性：单元测试和集成测试如何搭配、用什么框架、覆盖率要到什么程度。你还要懂得围绕可能的故障来做设计——如何处理故障（比如某个 API 撞上了 rate limit）、内建优雅降级，以及把故障的波及范围（blast radius）降到最小。此外，与其先写软件、之后再琢磨怎么给它加安全，"shift left"（左移）运动正把安全工作挪到生命周期更早的位置（在传统项目时间线上往左移）。正如所有开发者都在朝全栈开发者演变，如今许多开发者也在部分地扮演安全工程师。你现在可以用 AI 工具扫描代码找漏洞、检查依赖是否被供应链注入、审视云配置暴露的攻击面。但要把这件事做好，仍然需要一些安全方面的知识。

Scaling and operating in production.扩容并在生产环境中运维。

To serve real users, you will have to know how to deploy your software to production. You will benefit from knowing how to execute the software development lifecycle (SDLC) which, in addition to building and testing, includes configuring the deployment environment, deciding on release strategy, applying deployment automation (CI/CD), and understanding infrastructure as a service (IaaS).

要服务真实用户，你就得懂得如何把软件部署到生产环境。懂得如何执行软件开发生命周期（SDLC）会让你受益：它除了构建和测试之外，还包括配置部署环境、决定发布策略、应用部署自动化（CI/CD），以及理解基础设施即服务（IaaS）。

Operating in production requires putting in place observability tools, setting alerts, and managing incidents. Lastly, to scale your application, you should understand the real load and know how to scale servers, load-balance, and adapt your data infrastructure (via sharding, indexing, replication) or make architecture changes to allow your system to adapt to scale. Finally, understanding coding best practices like version control, code reviews, dependency maintenance, and how to manage technical debt helps you keep evolving your system over time.

在生产环境中运维，需要部署好可观测性（observability）工具、设置告警、处理线上事故。其次，要给应用扩容，你应当理解真实的负载，并懂得如何横向扩展服务器、做负载均衡、调整数据基础设施（通过分片、索引、复制），或者改动架构，让系统能够适应规模增长。最后，理解编码最佳实践——比如版本控制、代码评审、依赖维护，以及如何管理技术债——能帮你让系统随时间不断演进。

Coding agents have changed how we build software, including software that does not contain any AI components. Some parts of coding knowledge — like memorizing coding syntax — are becoming obsolete. But developers who deeply understand how software works vastly outperform those who vibe code without understanding.

coding agent 改变了我们构建软件的方式，包括那些完全不含 AI 组件的软件。编码知识中的某些部分——比如死记编程语法——正在变得过时。但深刻理解软件如何运作的开发者，会大幅胜过那些不求理解、只会 vibe coding 的人。

Understanding software fundamentals (in addition to AI) also helps you figure out what software can and cannot do. This makes them important context for how you use coding agents and shape the build. I will discuss these in the next two letters.

理解软件基本功（在理解 AI 之外）还能帮你搞清楚软件能做什么、不能做什么。这让它们成为你使用 coding agent、塑造整个构建过程时的重要上下文。我会在接下来的两封信里讨论这两点。

Keep building!

继续构建！
